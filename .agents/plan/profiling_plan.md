## Measurements and definitions

Use seconds for duration metrics and bytes for payloads; human-facing logs may render milliseconds. Use monotonic clocks for elapsed times on one host, wall time only for trace display. Never calculate durations by subtracting timestamps from different hosts.

| Question | Required observations |
| --- | --- |
| Request association and network connection | One trace from HTTP request handling through discovery, admission, every generation step and worker; request/session/step/route context. Separate process-level DHT join/reconnect duration and availability from request-level network checks. |
| Establishing the path | Discovery-lock wait, checkpoint/provider lookup, route selection, individual worker dial/admission and total setup. Record cold/reused connections. Path admission ends when all selected workers accept; lazy worker-to-worker connection setup remains separately visible on first forward. Tokenizer load/wait and encoding are separate preparation costs. |
| TTFT | HTTP request start to first sampled token received at the client server, including setup and preparation. Also measure first nonempty content body accepted by ASGI send for streaming, distinctly named; role/empty chunks do not count. Nonstream responses have no incremental text-delivery TTFT. Server send does not establish caller arrival; caller-observed TTFT remains a documented manual E2E observation. |
| TPOT and pauses | Timestamp every sampled-token arrival, including EOS; record individual arrival intervals and per-request mean `(last - first) / (sampled_count - 1)`. Omit TPOT with fewer than two sampled tokens. Count sampled tokens separately from text chunks and visible output. Preserve backpressure visibility; arrival intervals can include HTTP consumer delays. |
| Network traversal | Per-edge, per-step exchange elapsed time, matching remote handling time, estimated communication residual, request/reply wire bytes, dial time and effective exchange throughput. Separate prefill/decode and cold/reused links. Record route-step exchange duration and summed edge residual when complete without double-counting nested downstream exchanges. |
| Slow hops | Comparable rolling baseline, slow-event count, and trace event/attributes identifying the directed peer pair, step, payload size and connection state. |
| Worker/GPU processing | Session-lock wait, device-limiter wait, thread handoff, CPU preparation, host/device transfers, GPU stage execution, output preparation/serialization and downstream exchange as separate observations. Device execution includes embedding/final work where applicable. No waiting time is mislabeled GPU computation. |
| Slow GPU execution | Compare comparable GPU spans, recording worker/device, stage, prefill/decode, prompt or sequence length and context position. Show observed duration and comparison threshold. |
| Outcomes and overall cost | Total HTTP lifetime through body completion/disconnect, generation duration, prompt/sample counts, failures/timeouts/rejections/cancellations by phase, active requests/sessions and telemetry incompleteness. Do not convert normal cancellation into an execution error. |
| Device context | Periodic NVML utilization, used/total memory, temperature, power and clocks where supported; PyTorch allocator memory where useful. Samples describe the device, not exclusive per-request usage. Unsupported NVML fields are absent, not zero. Identify the actual CUDA-visible device by UUID/PCI identity, not an assumed physical index. |

CPU preparation, transfers and CUDA execution may overlap. Define boundaries and avoid claiming that overlapping timings add to exact wall time. CUDA events measure elapsed device-stream intervals, not pure kernel-active time. Read completed events without inserting a device-wide synchronization on every step solely for monitoring. Transfer/serialization spans must exclude nested downstream waiting.

## Cross-machine measurement contract

- Create the request trace before body validation. Keep it alive through actual response delivery and cleanup, including streaming errors/disconnects. Carry OpenTelemetry context explicitly across the asyncio/Trio bridge and worker threads. Concurrent requests must never share parents accidentally. Lifetime DHT-maintenance spans remain independent of a request.
- Inject/extract W3C trace context in bounded optional execution metadata for admission, forward and release. Preserve existing session/step/sender validation. Ignore malformed optional telemetry context without weakening protocol validation or logging payloads. Attach worker peer/device and stage identity to local spans/resources. A worker's outgoing exchange span parents the next worker's handling span.
- For each successful exchange, measure `exchange_seconds` on the sender from before frame send to complete reply receipt. Receiver returns its own monotonic `handling_seconds` from complete frame receipt until reply preparation, including queueing, local processing and downstream exchange. Compute `communication_estimate_seconds = exchange_seconds - handling_seconds`. The residual includes request/reply transport, framing/buffering and uncovered scheduling; it is neither exact one-way latency nor raw wire bandwidth. Time connection establishment separately.
- Validate received timing fields as finite, nonnegative and bounded by the corresponding exchange, with a documented tiny rounding tolerance. Missing/invalid timings yield an unavailable estimate and completeness metadata, not a fabricated zero or negative histogram entry. Legacy frames without telemetry continue to work. Worker timings are peer-reported observations, not trusted accounting.
- Each adjacent edge computes its own residual. Propagate only compact bounded totals/completeness counts back up the route when needed for the route-step sum; do not grow a per-worker trace array in replies. Preserve all execution error responses. Failed exchanges retain local error/timeout spans even when no remote reply exists.
- Record all request and operation metrics independently of trace export. For profiling, keep all traces with bounded export queues. IDs, exact routes, steps and unconstrained peer-pair combinations belong in traces/logs, not histogram labels. Use bounded metric dimensions and per-process worker resource identity.
- Do not capture prompts, generated text, token IDs, activation data, raw frames, credentials, or arbitrary exception messages in telemetry. Disable automatic exception payload capture where it could leak those values.

## Slow-operation detection

Implement a small bounded rolling-baseline detector for communication residuals and GPU execution, not a separate analytics service. Compare only the same operation kind and relevant stage/device or link, prefill/decode, cold/reused state and coarse power-of-two payload/sequence/context buckets. Use a rolling window of 64 valid observations and a warmup of 16. Flag a new value above three times the median of preceding observations with a 1 ms minimum threshold; do not compare a sample against itself. Bound group count with eviction and reset baselines on process restart. Describe these as heuristic outliers, not proof of hardware/network faults. Emit a trace event and warning containing safe identifiers, duration, baseline and threshold, plus a bounded-label counter. Missing measurements cannot trigger anomalies. Check that metadata, detector and exporter overhead stay bounded.

## Learnings

- End request spans at the ASGI delivery boundary, including rejected/error responses, and classify delivery failures there. Endpoint return and response headers do not establish completion.
- End admission spans before yielding the session; otherwise the trace includes generation in path setup even when its duration metric is correct.
- Optional peer timing must tolerate oversized JSON integers and wrong field types without affecting inference. Compare numeric bounds before conversions that can overflow.
- A newly recorded CUDA end event can remain pending after a blocking output copy. Wait on the specific end marker before reading elapsed time; do not silently discard the final request's GPU measurement.
- Apply exporter log filters to handlers, since ancestor logger filters do not process propagated child records. Carry the telemetry context explicitly into the Trio runtime thread.
